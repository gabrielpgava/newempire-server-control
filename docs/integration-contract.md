# Integration contract

The integration owner maintains migrations, HTTP handlers, CLI, release automation, and AGENTS.md. Domain packages do not import `internal/api` or own database migrations.

- Module: `github.com/gabrielpgava/newempire-server-control`; Go 1.27 (verified from go.dev at implementation time).
- `internal/model`: shared Instance, RuntimeStatus, LogLine and random 32-character hexadecimal IDs.
- All API paths start `/api/v1`. JSON uses snake_case. Lists are JSON arrays, errors are `{ "error": "English explanation" }`. Accepted jobs return a job object with ID.
- Sessions are same-origin HTTP-only cookies. Mutations require `X-CSRF-Token` from `/auth/session`. Authentication/setup endpoints enforce Origin separately.
- `GET /setup` returns `{required:boolean}`; `POST /setup` accepts token, username, password. `/auth/login`, `/auth/logout`, `/auth/session` (user and csrf_token).
- `/instances`: GET list, POST creation; `/instances/{id}` GET. POST `/instances/{id}/actions/{start|stop|restart}` returns job. GET `/status`, `/logs`, POST `/console` with `{command}`.
- GET `/instances/{id}/files?path=` list; GET `/file?path=` download/text; POST `/files` with `{operation,path,destination?,content?,confirm?:true}` returns job. Operations mkdir, write, move, trash. GET `/export?path=` streams ZIP.
- tus upload routes `/uploads/` (POST, HEAD, PATCH, DELETE). Upload metadata must include filename. POST `/instances/{id}/imports/preview` `{upload_id}`; POST `/imports/apply` `{upload_id,preview_hash,confirm:true}` returns job. Adoption/creation use explicit setup form.
- GET `/instances/{id}/backups`; POST `/backups` `{note}`; GET `/backups/{backupID}/download`; POST `/backups/{backupID}/verify`; POST `/backups/{backupID}/restore` `{confirm:true}`.
- GET `/instances/{id}/properties`, PUT same with `{properties:Record<string,string>,confirm:true}`; GET `/worlds`; POST `/worlds` `{operation,name,confirm:true}`.
- GET `/instances/{id}/players`; POST `/players` `{action,player?,value?}`.
- GET `/instances/{id}/mods`; GET `/mods/search?q=&minecraft_version=` requires the exact Minecraft version; POST `/instances/{id}/mods/plan` `{projects?:string[]}`; POST `/mods/apply` `{projects?:string[],plan_hash,confirm:true}`; PUT `/mods/policy` `{mode,interval_hours,window_start,window_end,timezone,postpone_players}`.
- GET `/fabric/versions`; GET `/java`; POST `/instances/{id}/runtime/plan` and `/runtime/apply` explicit versions and confirmation.
- GET `/jobs`, `/jobs/{id}`; POST `/jobs/{id}/cancel`; GET `/events` authenticated SSE invalidation stream.
- GET/POST `/schedules`; DELETE `/schedules/{id}`. Schedule fields instance_id, kind (backup/restart/mod_check), hour, minute, weekdays (0–6), timezone, enabled.
- GET `/audit`; GET/POST `/users` (owner only); GET/PUT `/settings`; GET `/updates`; POST `/updates/{check|stage|apply|rollback}`; GET `/healthz` is minimal public liveness, `/api/v1/health` authenticated.

All filesystem mutations and lifecycle changes run through durable jobs and exclusive instance locks. Domain operations return errors; the API never claims successful mutation on a failed operation. Unknown/external content is preserved. No world rollback is implicit in a content update.

## Concrete frontend wire schemas

All timestamps below are Unix seconds except Instance.created_at and log.time (RFC3339). Empty lists are `[]`, not null. HTTP 202 means accepted, not completed. Read job state/result before showing completion. User-visible errors are returned as `{error:string}`.

Roles: owner has all permissions and creates users/grants instance access; admin manages all instances/settings, but not owners; operator can lifecycle/console/players/backup on explicitly granted instances; viewer reads explicitly granted instances. Files, imports, restores, world/property mutations, mods, runtime and schedules require admin. Panel update reads require admin; update mutations, outbound credentials and user management require owner. Backup downloads require admin because archives contain credentials. A hidden button is not an authorization boundary.

`GET /auth/session`: `{user:{id,username,role,two_factor:boolean},csrf_token:string}`. Login body `{username,password,code?:string}` and setup body `{token,username,password}` return this same session. GET /setup is public `{required:boolean}`. Bootstrap token is read from the local protected data directory, never returned by HTTP.

Account security is self-service for every authenticated role: POST `/auth/password` `{current_password,new_password}`; POST `/auth/totp` `{}` generates an enrollment secret and `{password,secret,code}` enrolls it; DELETE `/auth/totp` `{password,code}` disables the current factor. Passwords are 12–1024 UTF-8 bytes. Successful credential changes revoke all account sessions. Owner DELETE `/users/{userID}` revokes a non-owner account, its sessions and instance grants; self/owner revocation is rejected. No cross-user factor override exists.

`Instance`: `{id,name,root,java_path,jar,minecraft_version,loader_version,memory_mb,port,rcon_port,eula,adopted,created_at}`. No credential is serialized.

`POST /instances`: `{mode:"create"|"import"|"adopt",name,java_path,jar?,minecraft_version,loader_version,memory_mb,port,rcon_port,eula:true,upload_id?,path?,preview_hash?,server_root?,reservation_id?,installer_version?}`. Create mode builds a new managed directory. Import requires a completed upload, preview hash, detected runtime versions, and exact `server_root`; only that subtree is installed, with rebased paths. Adopt requires an allowlisted path, preview hash, detected versions, `server_root:"."`, and its owner/path/hash-bound `reservation_id`; it never rewrites source files. The reservation preserves the instance ID, service account and creation time across permission-preparation retries; registration settings cannot change after the first attempt. All modes return a Job with instance_id reserved; successful job.result is `{instance:Instance}`. `jar` defaults to fabric-server-launch.jar for create; imports/adoptions require the explicit detected launcher. Names with surrounding whitespace/control characters, unidentified/custom launchers, runtime mismatches, insufficient Java and unsafe RCON configuration fail closed.

`POST /imports/preview` `{upload_id}`: `{preview_hash,files:[{path,size}],file_count,total_bytes,warnings:string[],launchers:string[],worlds:string[],server_root,minecraft_version,loader_version,java_required}`. This initial-instance preview rejects ambiguous source roots and reports rebased paths. `GET /adoptions`: `{roots:string[]}` (admin); `POST /adoptions/preview` `{path,reservation_id?}` additionally returns `reservation_id` and `service_account`. Applying a stale preview fails. Existing-instance file imports retain their path-preserving preview/apply contract and do not normalize a server root.

`GET /fabric/versions?minecraft_version=`: `{game_versions:string[],loader_versions:string[],installer_versions:string[]}` (stable only by default). `GET /java`: `[{path,major:number,version:string,error?:string}]`. Empty allowlist is an actionable error, not a guessed executable.

`GET /instances/{id}/status`: `{state:"offline"|"starting"|"ready"|"stopping"|"crashed"|"unknown",ready:boolean,pid?:number,uptime_seconds:number,memory_bytes:number,cpu_seconds:number,players:string[],detail?:string,disk_free_bytes?:number}`. Readiness requires more than a process. GET /logs: `[{time,message}]`; POST /console returns Job (HTTP 202), with `result:{output:string}` when successful.

Files list: `[{name,path,is_dir:boolean,size:number,modified_at:string}]`. GET /file downloads bytes; `?preview=true` returns `{path,content,etag}` for bounded UTF-8 text only, with sensitive files rejected. Write body includes `etag` to reject stale text. POST files returns a Job. Deleted paths move to an external recovery area, never disappear silently. Import preview inside an instance reports path-preserving files/counts/bytes/warnings plus conflicts and requires the preview_hash again on apply; it does not apply the initial-instance server-root normalization. Folder uploads are browser-created ZIPs, preserving relative names, sent through tus.

The stopped-panel CLI holds `panel.lock`, opens existing initialized state without migrations/key generation, and executes only its selected durable job. `backup_offline` creates a verified local ZIP and portable metadata without starting Minecraft, running HTTP workers or replicating offsite. A full-tree restore persists `restore-pending:<ID>` before swapping data; starts/mutations and retention remain blocked through ambiguous completion. Internal `restore_reconcile` requires `{use_previous:boolean,confirm:true}` and hashes the current tree against the selected verified snapshot before reconciling helper/database metadata; it never swaps worlds. Offline runtime recovery verifies retained launcher/properties against the pre-upgrade snapshot, preserves a verified inspection archive of the displaced data, and leaves world-format review latched when required. See the [recovery guide](disaster-recovery.md) for exact CLI confirmations and limitations.

Backups list: `[{id,instance_id,created_at:number,size:number,sha256:string,note:string,verified:boolean,local:boolean,offsite:null|object}]`. Remote-only records remain after local retention; remote HEAD metadata is not downloaded-byte verification. Admin POST `/backups/{backupID}/fetch-offsite` `{}` downloads and verifies a trusted remote record before local verify/restore/download controls become available. Backup verification returns Job. Restore preview: `GET /backups/{backupID}/preview` returns `{files:[{path,size}],file_count,total_bytes,warnings:string[]}`; restore POST requires `{confirm:true}` and returns Job. Archive and portable `.instance.json` identity/configuration preflight happen before stopping or replacing data. Backups are downloadable through authenticated range requests. Backup creation body accepts `{note,online?:boolean,format?:"zip"|"tar.zst"}`; offline is the default.

Worlds: `{active:string,worlds:[{name,path,active:boolean,dimensions:string[]}]}`. POST worlds operations `create` and `activate` require name and confirm. Creation is an empty world directory generated by Minecraft on the next start, not a fabricated valid world. Properties: `{properties:Record<string,string>,restart_required:boolean}`; PUT allows supported safe keys, preserves unknown keys and comments, and excludes RCON secrets.

Players: `{online:string[],whitelist:unknown[],operators:unknown[],bans:unknown[],ip_bans?:unknown[]}`. POST actions whitelist_add/whitelist_remove/op/deop/ban/pardon/kick/say/ban_ip/pardon_ip, with player and value as applicable. Operator cannot grant op or read/manage IP bans; those need admin. No invented player metadata.

Mods: `[{filename,sha512,project_id?:string,name:string,version?:string,version_id?:string,managed:boolean,pinned:boolean,update_available:boolean,reason?:string}]`. Search returns `[{project_id,slug,title,description,server_side?:string}]`. Plan returns `{plan_hash,actions:[{project_id,name,from_version,to_version,filename,reason}],blocked:string[],warnings:string[]}`. Apply requires projects (empty means updates to managed inventory), plan_hash and confirm. The API replans and rejects changed content. Pin/unpin/remove/disable/adopt operations use POST `/instances/{id}/mods/manage` `{operation,project_id,confirm:true}`. Exact-hash adoption requires a stopped server, verified backup and official compatible metadata; unknown content remains unmanaged. POST `/instances/{id}/modpacks/preview` `{upload_id}` returns a mod plan; `/modpacks/apply` requires `{upload_id,plan_hash,confirm:true}`; GET `/modpacks/export` streams an authenticated `.mrpack`. GET/PUT policy fields are as listed above. Default manual; automatic-safe is explicit opt-in, maintenance-window constrained.

`Job`: `{id,instance_id,kind,payload,state,progress,step,error,result,cancel_requested,cancellable,attempts,created_at}`. State queued/running/succeeded/failed/cancelled/interrupted. GET job returns `{job:Job,steps:[{time,progress,message}]}`. Cancellation returns `{ok:true}` only when accepted before a commit barrier. Schedules GET is the array of fields listed above, including next_run Unix seconds and last_job_id; POST returns the saved schedule.

Settings GET returns `{public_url,version,runtime_provider:"systemd",adopt_roots,java_paths,notifications:{configured:boolean},storage:{configured:boolean}}` plus nonsecret saved preferences. `public_url` is host-configured and cannot be changed through PUT. Settings PUT requires admin for retention and owner for outbound destinations/credentials. No saved credential is returned. Users GET array `{id,username,role,two_factor}`; POST `{username,password,role,instance_ids?:string[]}`. Audit array `{id,time,user_id,action,instance_id,detail}`.

Updates GET: `{current_version,repository,available:null|{version,notes,size,prerelease},state:string,detail?:string,history:unknown[],policy:{mode:"disabled"|"notify"|"automatic",channel:"stable"|"beta",interval_hours,window_start,window_end,timezone,postpone_until?:number}}`. Owner POST check/stage with `{}` and apply/rollback with `{confirm:true}` return Jobs. PUT `/updates/policy` saves the nonsecret policy and atomically preserves an omitted `postpone_until`; an explicit timestamp replaces it and zero clears it. POST `/updates/postpone` `{hours:24}` preserves other fields and returns the updated policy. Intervals are bounded to 1–168 hours. An unavailable signing key/helper is a clear failure; never fake an update. Runtime migration plan: `{plan_hash,warnings:string[],blocked:string[],java_required:number,changes:string[]}`; apply same selected versions, plan_hash, and confirm. GET `/instances/{id}/metrics` returns `[{time,state,memory_bytes,cpu_seconds}]`.
